Three ways you pay for the same answer twice

The paraphrase still hits the model

Someone asks the same thing with different words. An exact cache misses. You pay for the completion again.

receipt: "explain mutexes" · "please explain mutexes" · two bills

The agent retries until it looks done

A coding agent rephrases and asks again. Each try is a full chat call. The answer was already there.

receipt: agent → rephrase → model → rephrase → model

Or a cache keeps a “latest” forever

Word overlap treats similar text as the same question. Freshness still matters. A wrong hit is worse than a miss.

receipt: "what's the latest" · stored yesterday · should refuse

What it does

It decides whether the model should run at all

Exact first

Identical prompts never reach the model twice.

Same intent second

A paraphrase can reuse the stored answer when the adjudicator agrees.

Freshness can refuse

If the question needs a new answer, the model still runs. Fail-open if the adjudicator fails.

Default adjudicator is cloud Jev. Local opt-in: ADJUDICATOR=kev or laya. Streaming and tool calls bypass.

FAQ

Straight answers

Do I need OpenRouter?

For cloud Jev, yes. For local Kev or Laya, no — not for admits. Upstream chat still needs a model key unless you mock it.

Does it run on my laptop?

The proxy always does. The adjudicator can too, on a System One server you run yourself.

Streaming and tools?

Bypassed in this version. Those calls go straight upstream and are not cached.

Will it ever return a wrong hit?

Possible. Raise the intent threshold or run shadow mode while you validate. We do not claim zero false positives.

Where do the numbers come from?

Stars and npm installs load from the public APIs (fallback 10 and 367). Tests are the 55 that passed in vitest. The 2817 ms → 423 ms pair is one recorded demo. Word-overlap false-positive rate is from the offline eval on 103 pairs.
